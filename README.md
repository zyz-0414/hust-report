# HUST Report Skill

面向华中科技大学网络空间安全学院实验报告场景的 Codex skill，用于辅助起草、修订和检查 HUST 风格的中文实验报告。

本 skill 主要针对华中科技大学网络空间安全学院课程实验报告中常见的模板保护、目录更新、标题编号、图表题注、截图说明、正文格式和总结/感想写作要求。它适合与 `lab-report-writer`、`documents` 等文档处理能力配合使用，尤其适合需要在 Word 模板中保留封面、评分表、原创性声明等固定区域，同时规范正文内容和版式的报告任务。

> 非官方项目：本仓库不是华中科技大学或华中科技大学网络空间安全学院的官方项目，仅为个人整理的 Codex skill。

## 主要功能

- 识别并保护报告模板中的封面、前置页、评分表、报告要求页和原创性声明。
- 按实验报告正文区域应用标题、正文、目录、图表题注、编号和分页格式。
- 处理 Word 文档中常见的中英文字体槽、自动空格、目录格式塌陷、英文大小写异常和编号字号不一致问题。
- 检查封面下划线、目录加粗层级、图表题注加粗范围、长截图裁剪和原创性声明分页等模板细节。
- 强化网络空间安全专业实验报告的写作风格，使设计思路、实现过程、测试验证和结果分析更完整。
- 对截图和原始记录进行代表性选择，避免堆叠大量重复图片，并在需要时裁剪长截图的关键区域。
- 提供交付前检查清单，覆盖目录页码、标题分页、图表位置、正文格式和报告完整性。

## 适用场景

- 华中科技大学网络空间安全学院本科课程实验报告。
- 数字逻辑、程序设计、网络安全、密码学、系统安全等课程的中文实验报告。
- 已有 `.docx` 模板，需要保持模板固定区域不变，只调整正文内容与格式。
- 用户提供任务书、截图、原始数据或半成品报告，需要生成或完善正式实验报告。

如果课程模板或任课教师要求与本 skill 中的规则冲突，应优先遵循用户提供的最新模板和明确要求。

## 核心格式约束

本 skill 的 `SKILL.md` 已重新整理为紧凑版本，关键规则集中在前半部分，减少后续使用时漏读的概率。当前默认约束包括：

- 封面、评分表、报告要求页、原创性声明等区域默认视为受保护模板区域。
- 填写封面字段时，保留原有下划线，并让同类横线左右端点尽量对齐。
- 原创性声明的标题和声明正文应保持在同一页，除非模板或用户另有要求。
- 正文中文使用宋体；标题和图表题注中文使用黑体；英文、数字使用 Times New Roman。
- 不保留意外的等线、DengXian 或 Word 主题字体回退。
- 取消不必要的中英文、中数字和中符号间空格，并按需关闭 Word 的 `autoSpaceDE`、`autoSpaceDN`。
- 目录必须是真实 Word 自动目录。目录标题为黑体小二加粗居中；章级目录项加粗，其他目录项不加粗；英文术语保持原大小写，例如 `Scapy` 不应变成 `SCAPY`。
- 图题在图下方，表题在表上方；图号/表号加粗，其余题名不加粗。
- 长截图应裁剪到能说明问题的关键区域，避免整张长图直接破坏版面。
- 正文应避免不属于学生实验报告的写作口吻，例如“做了某操作，便于报告里展示”这类暴露报告组装过程的表述，应改写为实验目的、方法、证据或结果分析。

## 截图材料工作流

如果报告需要使用实验截图，请先让 Codex 阅读报告模板、任务书和评分要求，然后让 Codex 在当前报告目录下建立详细的截图子目录。完成目录规划后，再将截图按实验步骤、模块、测试用例或结果类型放入对应子目录，最后再使用 `$hust-report` 生成或修订报告。

推荐流程：

1. 先提供模板、任务书和评分要求。
2. 让 Codex 根据报告结构创建截图目录，例如 `screenshots/实验一/步骤1_环境配置/`、`screenshots/实验一/步骤2_功能测试/`。
3. 将截图放入对应目录，并尽量使用能说明内容的文件名。
4. 再请求 `$hust-report` 选择代表性截图、撰写说明文字并排版进报告。

这样可以减少截图遗漏、重复堆叠、图文不对应和后期排版混乱的问题。

## 安装

将本仓库克隆到 Codex skills 目录：

```powershell
git clone https://github.com/zyz-0414/hust-report.git "$env:USERPROFILE\.codex\skills\hust-report"
```

如果本地已经存在同名目录，可以先备份或删除旧目录后再克隆。

## 使用方式

在 Codex 中请求使用该 skill：

```text
$hust-report 请根据这个模板和任务书帮我写一份实验报告
```

也可以与其他文档技能配合：

```text
$hust-report 请保留封面和原创性声明，只修改正文、目录、图表题注和格式
```

强烈建议与 `$humanizer` skill 配合使用。`$hust-report` 更适合处理 HUST 网络空间安全学院实验报告的结构、模板、格式、图表和专业内容，`$humanizer` 则适合在报告初稿完成后，对实验总结、实验感想、意见和建议、问题分析等文字性段落进行二次润色，减少明显的 AI 写作痕迹，使表达更自然、更像学生本人完成的实验报告。

推荐用法：

```text
$hust-report 先根据模板、任务书和截图完成报告初稿
$humanizer 再帮我润色实验总结和实验感想，保持正式、自然，不要改变技术事实
```

如果用户有自己以前写过的报告段落，也建议一并提供给 `$humanizer` 作为风格参考，让最终文本更贴近个人写作习惯。

建议同时提供以下材料：

- 报告模板或已写好的 `.docx` 报告。
- 实验任务书、评分标准或课程要求。
- 实验截图、测试记录、原始数据或代码说明。
- 需要填写的姓名、学号、班级等封面信息。

## 交付前检查重点

使用本 skill 生成或修订 `.docx` 后，应至少检查：

- 封面字段和横线是否仍然像模板原样整齐。
- 目录是否为自动目录，页码是否更新，章级/非章级目录项加粗是否正确。
- `Scapy` 等英文术语大小写是否被 Word 样式错误改写。
- 正文、标题、题注、表格中的中文和英文数字字体槽是否正确。
- 图表题注是否只有图号/表号加粗。
- 汉字与英文、数字、符号之间是否存在多余空格。
- 长截图是否已经裁剪，图片说明是否在图片下方居中。
- 原创性声明是否按模板保持标题与正文同页。
- 正文是否没有“便于报告展示”等报告组装口吻。
- 是否已经通过 Word、PDF 或页面截图做过视觉检查。
